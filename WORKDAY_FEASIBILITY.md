## Workday wizard structure (UBC, representative)

After "Apply Manually" the user lands on Step 1 of a 7-step wizard:

1. **Create Account / Sign In** (current step) — email, password, verify password
2. My Information (name, address, phone, work auth)
3. My Experience (resume upload or manual entry; education; skills)
4. Application Questions 1 of 2
5. Application Questions 2 of 2
6. Voluntary Disclosures (EEO, gender, race)
7. Review

This is identical or near-identical across UBC, Canadian Tire, Langara, QuadReal — meaning **a single Workday wizard adapter** would cover ~70% of the queue once the account-creation hurdle is past.

## Choice picker structure (universal)

After clicking the JD-page "Apply" button, every Workday tenant shows a "Start Your Application" modal with three options:
- **Autofill with Resume** (primary, blue) — uploads resume, parses, then proceeds to wizard
- **Apply Manually** (secondary) — proceeds to wizard with empty fields
- **Use My Last Application** (tertiary) — requires existing login

Both "Autofill with Resume" and "Apply Manually" land on the Create Account screen. There is no path that bypasses account creation.

Note: **"Autofill with Resume" is interesting** — it uploads + parses the .docx before account creation. This means if the worker uploads Kiran's tailored resume here, fields auto-fill on later steps, reducing manual form-filling. Worth using over "Apply Manually".

## Recommendations for v1

### Option A — Build account creation now (~6 hours added scope)

- Worker generates a strong password per tenant (or reuses one — security trade-off)
- Worker fills Create Account form, submits
- Worker waits for verification email (or OTP) — polls Gmail via either:
  - **Gmail App Password + IMAP** (5-min setup, app password generated by Kiran)
  - **OAuth** (multi-hour, production-grade)
- Worker clicks the verification link or enters OTP
- Worker stores `(tenant, email, password)` in Upstash under `user:kiran:tenant_creds:{tenant_host}`. Encrypted-at-rest only — Upstash is a shared service.

### Option B — Re-source 10 Greenhouse / Ashby URLs instead

- Greenhouse anon-apply is the default. Demo-ready in hours, not days.
- Lose Workday coverage in v1 but ship working end-to-end faster.
- Ashby is similar — no account required, single-page form.

### Option C — Hybrid: Workday-account in v2, Greenhouse end-to-end now

- Pivot the autonomous loop to Greenhouse for the rest of tonight
- Document Workday account creation as a v2 work item
- Tomorrow morning we have a working Greenhouse demo + a clear Workday plan

**My recommendation: Option C.** It maximizes shippable progress in the time available, gives Kiran a real Greenhouse demo, and surfaces the account-creation question to Harshit cleanly tomorrow rather than burning hours on it tonight.
